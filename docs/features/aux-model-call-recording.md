## ① 需求定义

为了学习上下文、工具往返和协议适配，能够查看每次模型 HTTP 调用实际发送的 JSON 与接收内容，而不把一次 Run 简化成一次模型调用。

- 默认关闭，可在设置中保存开关；配置按 Run 开始时读取。
- 记录接口、请求 JSON、原始 SSE 文本、解析后的回复/工具调用、usage（若有）、状态、耗时与安全错误，关联 Run 与 Conversation。
- 本地持久化，失败、取消、服务重启后保留已接收数据。
- 不保存鉴权 headers，不泄漏配置密钥及 URL 凭证，包括响应回显与错误消息。
- 每轮执行过程可按需展开模型调用，支持 JSON/原始内容折叠、复制、刷新与重开页面读取。
- 明确提示正文包含对话和文件内容；关闭不删除历史。

范围外：完整 Trace/Span、费用计算、自动重试、录制回放引擎、远端上传、记录清理管理，以及完整 S2 主题。

## ③ 技术方案与安全影响

- `recording.py` 的任务局部作用域隔离并发 Run；Provider 在每次 HTTP 调用创建 Recorder，Store 分配 Run 内序号。
- 专用表存储请求与增量响应，和普通事件/日志分离；API 返回结构化记录，SDK 由 OpenAPI 生成类型。
- 原始内容指 HTTPX 解码后、保留换行并经过脱敏的文本；并非字节抓包。解析在 `[DONE]` 结束，未接收的尾部不在保证范围内。
- URL 删除用户信息、全部查询参数与 fragment；配置密钥、URL 凭证及常见 URL/JSON 编码回显脱敏。不保存请求/响应 headers。跨 HTTP 片段的凭证前缀暂缓持久化，最终仍替换为脱敏标记。
- 不改变工具权限、文件访问边界、模型请求参数或外部调用目的地；不额外请求 usage，服务端未提供则显示 null。
- 网页展开时才查询，运行期间每 2 秒刷新。先读 Run 状态再读记录，避免最后一次调用遗漏；更换 Run 时重建组件，丢弃迟到请求。
- 现有 SQLite 同步写入方案的代价是长响应下的内存与磁盘开销；当前无清理、分页与大小上限。

## ④ 实现记录

接续工作区已有实现，补充修复：

- 流失败/取消时不再把暂缓的密钥残片明文写回；选择最长匹配前缀。
- 脱敏只作用于不可信正文与接口字段，保留内部字段名与存储 ID；凭证恰与 `status`、`model` 等内部字符串相同时也不破坏记录终态与更新定位。
- URL 中凭证被服务端回显时同样脱敏，包括 Basic 凭证编码。
- 非法 usage、工具索引、流内错误对象等转换为安全 ProviderError，避免原始解析异常泄漏正文。
- 保留 JSON 错误 body；整理响应记录推断后的 finish_reason；支持 CR、CRLF、LF 和跨 UTF-8 字节片段。
- 修复网页终态查询顺序，按 Run 重置记录面板；历史轮次未加载工具事件时不显示虚假的零次工具调用。
- 验证设置加载完成后才挂载表单，防止覆盖已保存开关。
